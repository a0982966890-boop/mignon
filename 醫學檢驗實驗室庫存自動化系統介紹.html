背景說明

為什麼實驗室需要這套系統？

醫學檢驗科的試劑庫存管理，長期面臨幾個重複性高、卻又不容出錯的挑戰：每日需手動登入庫存系統確認存量、在警戒值以下的品項需要人工比對再下訂單、Beckman 出貨單需要手動逐筆輸入入庫資訊、每個月初需要手動建立新的試算表追蹤記錄。

這套自動化系統的核心思路，是把所有「每次做法都一樣」的重複步驟交給程式自動完成，讓檢驗師的時間回歸到需要專業判斷的工作上，同時保留關鍵的人工確認節點，避免因自動化程度過高而失去稽核能力。

使用者角色

系統對不同層級的意義

這套系統的設計兼顧了實驗室三個層級的需求，主管看到的是整體庫存風險，組長看到的是日常操作效率，儀器主要負責人則直接受益於減少重複性手動作業。

🏥
實驗室主管

透過 LINE 推播即時掌握新增低庫存品項。月底可直接查看 Google 試算表的完整庫存趨勢與短效期清單，作為採購預算與風險管理的依據，不需要每天登入系統查閱。

📋
組長

每日盤點結果自動寫入 Google 試算表，低庫存品項清單自動彙整。每月固定的耗材訂單與 DXI 專車訂單，調整數量後即可一鍵觸發，不需要手動逐筆操作保吉系統。

🔬
儀器主要負責人

Beckman 出貨單上傳 Google Drive 後，AI 自動辨識轉換為試算表格式，人工確認資料正確後執行入庫，免去手動逐筆輸入批號、效期、數量的重複作業。新批號說明書連結也會自動搜尋帶入。

作業流程

系統每日如何運作？

系統的主幹是一條每日自動執行的流程，搭配數個人工手動觸發的節點。自動的部分負責監控與彙整，需要人工判斷的步驟（例如確認 AI 辨識結果、確認訂單內容後再下單）則保留手動觸發，確保稽核責任清楚。

每日 07:30

庫存自動盤點 自動

登入保吉庫存系統，抓取免疫 Beckman DxI 800 所有試劑的今日存量，與昨日比對計算差異量，結果寫入當月 Google 試算表對應的日期分頁。

盤點完成後

低庫存預警通知 自動

比對每個品項的警戒值設定，若有新增的低庫存品項（原本充足、今天才跌破警戒值），立即透過 LINE 推播通知，並更新「低庫存補貨清單」分頁。

收到通知後

急訂單下單 手動觸發

確認低庫存清單後，在 GitHub Actions 手動觸發急訂單 workflow，系統自動逐筆搜尋品項、填入訂購量、送出。執行完成後印出已送出、已跳過（數量為 0）、失敗三組統計摘要。

貨到時

PDF 出貨單辨識 手動觸發

將 Beckman 出貨單 PDF 上傳至 Google Drive 指定資料夾，觸發 PDF.py，Gemini AI 自動辨識並轉成試算表。人工確認資料正確後，再觸發試劑入庫.py 自動填寫入庫資訊。

每月月初

新月份試算表自動建立 自動

每月第一次執行庫存盤點時，程式自動建立當月的 Stock_YYYY_MM 試算表，並從上個月的分頁複製「每月耗材訂單」與「DXI 專車訂單」的固定品項清單，訂購量自動歸零，等待當月填寫。

功能模組

系統包含哪些功能？

共八支腳本，功能分工清楚，共用底層模組（utils.py）維護，任何一支出問題不會連帶影響其他腳本。

每日庫存盤點 · 每日 07:30 自動執行

爬取保吉系統庫存數據，比對警戒值，更新 Google 試算表當日分頁與低庫存補貨清單，新增低庫存時發送 LINE 通知。

急訂單 / 專車訂單 / 耗材訂單 · 手動觸發（三種參數共用一支腳本）

從對應 Google 試算表分頁讀取品項與訂購量，自動逐筆搜尋並填入保吉訂購系統。數量為 0 或空白自動跳過並記錄；填寫失敗不會強制送出，執行完成後印出摘要。

PDF 出貨單辨識 · 手動觸發

下載 Google Drive 上的 Beckman 出貨單 PDF，透過 Gemini AI 辨識品項編號、批號、效期、數量，輸出為 Google 試算表。出貨單格式異動通常不需要修改程式碼。

試劑入庫 · 手動觸發（人工確認後執行）

讀取 PDF 辨識後的試算表，自動登入保吉系統填入批號、效期、數量並送出入庫。效期空白者自動補上執行當日起一年（適用無效期限制的耗材）；格式有誤者填入 0000-00-00 標記供人工核對。

新批號及文件更新 · 手動觸發

盤點多批號在庫品項，標記最新批號（NEW LOT），自動搜尋 Beckman 官網繁體中文說明書 PDF 連結並以 HYPERLINK 公式寫入。同步更新短效期清單（60 天內到期品項），每次執行必定更新，不論當天是否有新批號。

風險控制

自動化的同時如何確保準確性？

自動化不等於無監督。這套系統在設計時刻意保留了幾個人工確認節點，避免錯誤被自動放大。

環節 風險點 應對設計
AI 出貨單辨識 批號、效期辨識錯誤 PDF 轉換與試劑入庫拆成兩支獨立腳本，中間保留人工確認試算表的步驟，確認無誤再執行入庫
訂單送出 數量填錯或誤送出 數量為 0 或無法解析者自動跳過並記錄；填寫失敗不會強制點送出；每筆執行完印出三組統計摘要供核對
效期輸入 AI 辨識日期格式錯誤 效期解析加入年月日合理性驗證，格式錯誤填入 0000-00-00 而非猜測一個看似正確的錯誤日期
月初建檔 新月份試算表不存在導致資料遺失 程式自動建立當月試算表並從上月複製固定品項分頁，多批號清單完整保留不歸零（避免誤判為全新批號）
LINE 通知 重複通知造成干擾 只有「新增的」低庫存品項才會發送通知，已知的低庫存品項不重複推播

技術架構

系統運作需要哪些環境？

這套系統建立在幾個免費或低成本的雲端服務之上，不需要架設自己的伺服器，所有排程與腳本執行都在 GitHub Actions 上完成。

雲端服務

  • Google Sheets（庫存試算表）
  • Google Drive（PDF 儲存）
  • GitHub Actions（排程執行環境）
  • LINE Messaging API（推播通知）
  • Gemini AI API（出貨單辨識）

憑證管理

  • GCP 服務帳戶金鑰（日常讀寫）
  • 個人 Gmail OAuth 憑證（建立新檔案用）
  • 保吉系統帳號密碼
  • LINE Token
  • 以上均存放於 GitHub Secrets

腳本語言與主要套件

  • Python 3.10
  • Selenium（網頁操作）
  • gspread（Google Sheets 存取）
  • google-genai（Gemini AI）
  • pandas（資料處理）

注意事項

  • OAuth Token 需設為「正式版」避免 7 天過期
  • 服務帳戶儲存配額為 0，建檔須用個人帳戶
  • 新建試算表須共用給服務帳戶方可讀寫
  • GitHub Actions 外部排程不受閒置停用影響

導入建議

其他實驗室如何開始？

這套系統是從實際日常工作痛點出發建立的，如果您的實驗室也在使用保吉庫存系統與 Google Workspace，以下是建議的導入順序。

1

建立基礎設施

申請 GCP 服務帳戶、設定 Google Sheets 試算表結構（rule 分頁填入品名、保吉編號、警戒值、訂購量）、建立 LINE Messaging API 頻道、取得 Gemini API 金鑰，全部存入 GitHub Secrets。

2

先跑「每日庫存盤點」

這是整個系統的資料來源，建議先把這支跑穩，確認能正確抓取庫存數據、寫入試算表、發送 LINE 通知，再往下推進其他功能。

3

接入訂單腳本

在 Google 試算表建立「每月耗材訂單」和「DXI 專車訂單」分頁，填入你們實驗室的固定採購品項，先用少量品項手動測試，確認下單流程正確後再正式使用。

4

導入 PDF 入庫流程

上傳一張真實的 Beckman 出貨單測試 AI 辨識效果，確認欄位對應正確、效期格式能被正常解析，再正式納入入庫 SOP。建議第一次由熟悉系統的人全程陪同確認。

5

調整警戒值與訂購量

運行一到兩個月後，根據實際消耗速率微調 rule 分頁的警戒值設定，讓低庫存預警的時間點更符合你們實驗室的補貨週期，這是讓系統真正「貼合實際運作」最重要的調整。
